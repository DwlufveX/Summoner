当前 Steam `Version.txt` 为 `1.7.4977 rev1248`；上述信息来自本机文件，只记录本次测试环境。公测后续更新需要重新核对。

本轮在忽略目录 `.tools/dotnet` 安装独立 SDK 10.0.402，不修改系统 SDK/PATH。Harmony 分别引用 Workshop 的 1.6、1.7 目录。游戏 API 共用数据代码，未初始化测试对象的创建入口按版本使用 FormatterServices/RuntimeHelpers。

`LoadFolders.xml` 每版只加载 `/` 与自己的版本目录；根目录不再放程序集。两个 DLL 分别输出到 `Mod/1.6/Assemblies`、`Mod/1.7/Assemblies`，构建缓存按版本隔离。包检查验证目标框架、加载目录、元数据、XML/贴图及只包含两个 Mod DLL。

真实存读验证运行于独立完整游戏副本，测试模块从 Mod 构造起捕获 Log.Error，不屏蔽保存、交叉引用或加载后初始化错误。每版生成真实主人、地图兽和灵境兽，写入成长/奖励/伤势/需求/嵌套物品并执行两轮保存与读档。证据见[本轮结果](tasks/02_DUAL_VERSION_RESULT.md)。

0.3.0-dev 的三兽与契约入门进一步通过两版真实觉醒/开笼/契约/移动任务、轮换、风刃命中、未打开牢笼保存/读回、两轮实体存读及加载后继续操作；原数据底座场景重新跑过。当前包是 0.3 开发版，详见[三兽与契约结果](tasks/03_DRUID_CONTRACT_RESULT.md)。

## 后续实施要求

- 共享玩法与数据定义，版本差异集中到工程配置和少量适配代码。
- 分别编译和记录 1.6、1.7 结果，使用版本加载目录隔离不同目标程序集，避免同时加载两份数据组件。
- 美术源稿可共用；图形入口与游戏显示分别验收。
- 存档必须各自完成完整保存、引用解析与加载后初始化。两版各自可读写不等于跨版本迁移已经成立。
- 测试工具的游戏目录和 Workshop 路径可传参，不依赖当前 Steam 必须仍是 1.6。
- 发布前验证两版加载目录、依赖和运行结果；1.7 公测更新后重新跑必要回归。
