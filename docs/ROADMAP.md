# 大型召唤师 Mod 开发路线

更新日期：2026-10-28。最近一次记录的游戏验收：2026-10-14。本次整理开发顺序与协作入口，不代表新增功能已经完成。

## 设计与实现边界

唯一开发方向为[召唤师流派系统设计需求 v0.10.2](References/召唤师流派系统设计需求v0.10.md)。玩法关系与规则收口见[游玩逻辑与成长体系](GAMEPLAY.md)，当前实现进度见[工程状态](STATUS.md)。

2026-10-14 用户确认后续同时支持 RimWorld 1.6 和 1.7 公测版。两版的编译、加载与存档验收须分别完成，见[双版本兼容目标](COMPATIBILITY.md)。

工程已移除旧版玩法，保留可复用资源与构建工具。数据底座、灵境容器、双版本实体存读与入门契约流程已完成。四阶成长结算、沉睡治疗和死亡状态机仍待实现。`References/SummonerClass.zip` 只作历史资源参考，不直接参与编译；历史需求和交付清单不得覆盖权威需求。

2026-10-28 调整后续内容路线：优先联动奇幻生物包，暂停独立扩绘召唤兽。来源包提供生物本体，Summoner 维护契约、编队、成长与灵境。现有内置三兽保留作原型和兼容；外部候选尚未适配，见[联动方案](INTEGRATIONS.md)。该决定调整生物来源，不把原生技能、成长或依赖直接视作兼容。

## 接下来的里程碑

各阶段按下面的验收条件推进，不预设发布日期。先用一个生物包的少量普通物种打通联动，界面资源与测试并行；不同时对整张候选名单做未经验证的支持声明。

| 里程碑 | 工作内容 | 验收条件 |
|---|---|---|
| 0. 首包联动 | 核对来源 ID、定义、依赖与版本，建立档案查询和物种白名单，接入原生个体 | 契约、控制、攻击/技能、召回/轮换、两轮存读及缺失来源场景通过；普通野生个体保持原行为 |
| 1. 规则收口 | 奖励次数、工作经验单位、参与击杀口径、经验速度、熟练度与槽位解锁、主人失效规则 | 把 39 次升级与 40 次奖励预算、解锁阈值、死亡记录归属等问题写成明确规则；不在代码里默选互相冲突的方案 |
| 2. 成长结算 | 战斗/工作经验、A 类属性/变异选择、B 类技能/工作选择、主人反哺 | 连续升级不漏奖；未决候选落档且读档不重抽；达到上限的选项正确退出池 |
| 3. 突破与生存 | 灵质来源与消耗、手动突破、锁血退回、沉睡、死亡、复活、主人失效 | 普通段重置与永久成长保留正确；濒死、冷却内真死、复活、槽满及跨状态存读分别通过 |
| 4. 德鲁伊 MVP 完整化 | 完整救援、三兽专属技能、清洁/医疗与工作等级、UI、威胁点和数值调整 | 从觉醒到二阶可连续游玩；两版基础显示、鼠标操作与存读通过，并记录培养用时与袭击强度 |
| 5. 后续血脉 | 按 Phase 2/3 引入新血脉与终局玩法 | 延用已有契约、成长和生存机制，逐条验证 DLC 需求与兼容性 |

## 美术与协作

1. 暂停独立制作三兽四向，优先使用来源生物包自带的贴图、身体、声音和原生能力；资源不复制入本项目。
2. 自制资源聚焦召唤师图标、编队界面与必要的召唤效果，保留原稿和来源说明。
3. 每个里程碑可分别认领代码、美术、测试/文档任务；一个任务用一个功能分支，通过 Pull Request 合并。
4. 测试优先覆盖连续升级与未领奖保存、轮换/死亡与持有关系、未打开的救援牢笼、主人失效，以及实际 UI 操作。

首次加入项目见[协作说明](../CONTRIBUTING.md)。原型预览见[仓库首页](../README.md#内置三兽原型预览)，具体适配要求见[联动方案](INTEGRATIONS.md)。

## MVP 实施顺序与已有基础

1. 主兽规则已确认：首版每槽仅主兽上场，三兽轮换，之后多槽与容量解锁同场；继续收口成长次数、工作经验单位、熟练度和契约位解锁。
2. 建立召唤师、契约槽、兽成长、灵魂界保存及冷却数据模型。
3. 接入狼、熊、鹰实体，验证征召、需求、工作与基础护甲。
4. 完成觉醒、救援、契约、备用兽轮换和上场容量，形成获取与使用循环。
5. 接入经验、三选一队列、技能工作成长、主人反哺与突破。
6. 接入灵质、锁血退回、沉睡、复活与主人失效规则。
7. 完成 UI、威胁点计入和跨状态存读档，验证从觉醒到二阶的完整流程。
8. 按实测升级时间、资源收入、死亡损失及袭击强度调整数值，再扩展后续阶位与血脉。

验收使用大型版新场景；历史代码与测试结果只存作参考，不作为当前实现的证据。
