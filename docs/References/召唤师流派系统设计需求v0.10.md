# 召唤师流派 Mod —— 系统设计需求 v0.10.2（Codex 实现用）

> 本文档用于直接交给 Codex（或任意编码 Agent）实现 RimWorld 模组「召唤师流派 / Summoner Class」。
> 取代 v0.10.1 / v0.10 / v0.9.1 / v0.9 / v0.8。v0.10.1 是 Codex 审阅 v0.10 后的规则澄清与数值重做；**v0.10.2 在 v0.10.1 基础上，针对"成长选择预算"与"沉睡冷却作用域"两处遗留歧义做最终收口**：
> - **成长选择预算明确**：每升 1 级只给 1 次 A 类 3选1，普通属性与特殊变异**共享同一份 40 次升级选择预算**；算例改为"分配式"而非"全投近战 + 叠加体型"。
> - **沉睡冷却作用域明确**：冷却**作用于单只兽**（该兽 3 日内不可召回）；**槽位不被锁**，同槽其他备用兽可随时顶上主兽（切换主兽无 CD）。
> - **备用兽容量口径澄清**：`reservePerSlot` 只计**备用兽**，主兽不计入；灵魂界总容量 = 主兽总数 + 备用兽总数（备用兽 ≤ `contractSlots × reservePerSlot`）。
>
> 本文档为当前唯一权威需求版本。

## 2. 术语与数值体系

### 2.1 五个独立概念（v0.8 三个概念的扩展，彻底消除"Tier"一词多义）

| 概念 | 符号 | 范围 | 含义 | 拥有者 | 变化方式 |
|---|---|---|---|---|---|
| **体量** | `occupySlots` | {1, 2} | 该兽在场上占几个**上场容量** | 每只兽（按 RaceDef） | 由物种/进化后的 RaceDef 决定，**固定不可变** |
| **阶位** | `tier` | {1..4} | 该兽突破次数 | 每只兽 | 满 40 级自主突破 +1 |
| **阶内等级** | `tierLevel` | {1..40} | 当前阶位内的等级 | 每只兽 | 杀敌 + 日常工作 |
| **上场容量** | `maxSlots` | 1,2,3,4… | 同一时刻能在场上出现的兽的 occupySlots 总和上限 | 召唤师 | 通过仪式/熟练度阈值增长 |
| **契约位（血脉槽位）** | `contractSlots` | 1,2,3… | 召唤师能同时绑定几只兽。每个槽位 = 1 只**主兽** + 最多 `reservePerSlot` 只同血脉**备用兽**。 | 召唤师 | 通过仪式/熟练度阈值增长 |
| **备用兽上限** | `reservePerSlot` | 3（MVP 固定） | 每个契约位可存放的**同血脉备用兽数量**（主兽不计入此项） | 召唤师 | MVP 固定 3；后续可 `baseReservePerSlot + floor(contractSlots/2)` 扩展 |
| **血脉阶** | `schoolTier` | {1..4} | 召唤师对某血脉的造诣 | 召唤师/每血脉 | **Phase 2 再做**，MVP 不写 |

> **关键澄清**：
> - `maxSlots` 是**上场容量**（Active 兽的 occupySlots 之和 ≤ maxSlots）。
> - `contractSlots` 是**契约位 / 血脉槽位**（你拥有几条血脉通道）。每个槽位可绑定 1 只主兽 + 最多 3 只同血脉备用兽。
> - 初始：`maxSlots=1`，`contractSlots=1`。
> - 举例：你有 2 个契约位（德鲁伊槽 + 亡灵槽），各绑了一只 1 栏主兽 + 若干备用兽，则 `maxSlots=1` 时你只能召 1 只上场，另 1 只沉睡；`maxSlots=2` 时才能同时召 2 只。
> - **容量口径（v0.10.2）**：`reservePerSlot` 只数"备用兽"，主兽永远单独占 1 个位置、不计入该上限；灵魂界总在栏数 = 主兽总数 + 备用兽总数，其中备用兽 ≤ `contractSlots × reservePerSlot`。

## 3. 栏位（Slot）模型（v0.10.1 重定义：契约位 = 血脉槽位）

### 3.1 两种栏位
- **契约位（contract slot = 血脉槽位 / roster slot）**：召唤师与某条血脉的"契约通道"。每个契约位有：
  - `bloodline`：该位绑定的血脉。第一次契约后**固定**，不可更改。
  - `boundBeast`：当前绑定并使用的**主兽**（active / retreated / sleeping）。
  - `reserveBeasts`：该血脉的**备用兽列表**，存放在灵魂界。上限 = `reservePerSlot`。
- **上场容量（maxSlots）**：记录"场上同时能站多少只"。是 occupySlots 的总和上限。

### 3.2 一个契约位到底能存几只兽？（容量计算口径，v0.10.2 澄清）
- **主兽（1 只）**：每个槽位始终有 1 只主兽（active / retreated / sleeping 三态之一）。主兽**不计入** `reservePerSlot`。
- **备用兽（最多 `reservePerSlot` 只）**：同血脉、存放在灵魂界备用列表的兽。`reservePerSlot` 这一上限**只约束备用兽的数量**。
- **MVP 固定 `reservePerSlot = 3`**：每个血脉槽位 = 1 主 + 最多 3 备，至多 4 只同血脉兽同时在"在栏"状态。
- **灵魂界总容量**：`总在栏兽 = 主兽总数 + 备用兽总数`，其中 `备用兽总数 ≤ contractSlots × reservePerSlot`。例如 2 个契约位（各 1 主 + 3 备）= 2 主 + 6 备 = 8 只在栏，备用兽上限 6 已满足。
- 不再用 `max(3, contractSlots)` 这种混淆口径。

### 3.3 契约规则
- **首次契约**：消耗一个**空的/自适应的**契约位，该位从此绑定该兽的血脉。该兽成为主兽。
- **同血脉新兽契约**：若该血脉槽位的备用兽未满（`< reservePerSlot`），新兽**直接加入备用列表**；若已满，必须释放/牺牲一只备用兽，或另一条血脉槽位有空位。
- **切换主兽**：把当前主兽设为"reserve"，从备用列表选一只召为主兽。此操作**不占用沉睡 CD**（见 §3.4）。
- **跨血脉**：必须拥有另一个空的/自适应的契约位；不能把德鲁伊槽改成亡灵槽。

### 3.4 沉睡（Sleep）与召回（Recall）—— 区分主兽切换（v0.10.2 澄清作用域）
- **沉睡**：让当前在场上/active 的**主兽**强制进入灵魂界休整，状态变为 `sleeping`。
  - **冷却作用域 = 单只兽**：该兽进入 `sleeping` 后，**3 游戏日（`sleepCd`）内不可被召回**（不能重新上场）。
  - **槽位不被锁**：同一契约位内的**其他备用兽不受影响**，可以随时被顶上主兽并召唤（切换主兽本身无 CD，见 §3.3）。即"沉睡一只、换另一只顶上"是允许的。
  - **沉睡的意义**：灵魂界中该兽获得强制休整/缓慢恢复（wounds 暂停恶化、不消耗补给）；3 日是"它暂时不能上场"的代价。
  - 设计目的不是"限制战斗中换兽"（那由 `maxSlots` 卡上场数量即可），而是给一只受伤/疲劳的主兽一个"下场养伤、暂不可召回"的选项，同时不剥夺你用备用兽顶替的能力。
- **召回**：把灵魂界中 `retreated` 状态的主兽或备用兽召到场上。
  - `retreated` = 锁血退回后、未沉睡，只是暂存灵魂界，**可随时召回**。
  - `sleeping` = 玩家主动选择的沉睡，**3 日内该兽不可召回**（其他兽照常）。
- **主兽切换 vs 沉睡**：
  - 如果只是让主兽回灵魂界、换一只备用兽上场 → 这是**召回/切换**，没有 3 日 CD，立刻可换。
  - 只有玩家明确点击"沉睡"才进入 3 日 CD，且该 CD 只绑在那一只兽身上。

### 3.5 "占栏数固定"与"奇遇进化占 2 栏"
- `occupySlots` 对**一个具体的 RaceDef** 是固定的。
- 进化/奇遇可能把兽变成**另一个 RaceDef**（例如 1 栏灵狼 → 2 栏灵能巨狼）。
- 这种进化只有在**当前 maxSlots ≥ 新 occupySlots** 时才允许；否则进化被阻塞，或提供一条保持 1 栏的替代分支。

### 3.6 "在栏"定义
- 文档中"在栏"均指**已契约、未释放、未真正死亡**的兽，包括：
  - 主兽（active / retreated / sleeping）
  - 备用兽（reserve）
- 释放（abandon）或真死后，兽不再"在栏"，其占用槽位清空。

## 4. 成长与软重置（v0.9 完整算例）

### 4.1 基本定义（v0.10.1 重写，v0.10.2 澄清选择预算）
- **基线值 `baseStat`**：Tier1 Lv1 时该属性的实际数值（例如近战伤害 = 20）。
- **普通属性**：近战伤害 / 攻击速度 / 最大生命 / 移速等。只在每次升级后的 **3选1（A 变异）** 中选择对应选项时获得成长。
- **普通属性成长值**：`g(tier) = baseStat × 0.10 × 1.5^(tier-1)`。
- **普通属性硬上限**：`cap(tier) = baseStat × (3 + 2 × tier)`。
  - Tier1 = `baseStat × 5`；Tier2 = `baseStat × 7`；Tier3 = `baseStat × 9`；Tier4 = `baseStat × 11`。
  - 该上限只约束"普通属性累加段"，特殊变异乘区可让最终值超出上限。
- **普通属性无"每级递减"**：普通属性每次选择固定获得 `g(tier)`，不会因为"选了很多次"而递减；其唯一约束是上方的**硬上限**（到顶后该选项从池中移除）。（与之相对，特殊变异同类重复选择会递减，见下。）
- **特殊变异**：体型 / 多肢 / 护盾器官 / 再生腺体 / 双火工作兴趣等。永久跨阶保留，作为**乘区**。
- **特殊变异层数上限**：体型 ≤ 3 / 多肢 ≤ 2 / 护盾/再生等部件 ≤ 2；同类特殊变异再次选择时收益**递减**（`0.85^(n-1)`）。
- **选择预算（v0.10.2 关键）**：每升 1 级只给 **1 次 A 类 3选1**，选项既可以是普通属性，也可以是特殊变异。**普通属性成长与特殊变异层数共享同一份"40 级 = 40 次选择"的预算**——想多拿体型，就得少投普通属性，二者不能"全投 + 叠加"同时满额。
- **突破继承**：新阶普通属性基线 = `baseStat + inheritFrac × (prevTierCap - baseStat)`，其中 `inheritFrac = 0.35`。
  - 继承的是上一阶的**硬上限值**，不是玩家实际达到的数值——避免"没练满就吃亏"，也让公式固定可预测。
- **突破时保留/重置清单**：
  - **重置**：普通属性数值、普通属性已投入次数、阶内等级 → 1。
  - **保留**：特殊变异层数与计数、技能/工作等级、技能/工作选择记录。
- **护甲地板（v0.10）**：护甲既是普通属性之一，又拥有 §7.1 的「自带基础护甲」自动成长地板（`ArmorRating_Sharp/Blunt` 随阶/级由 `BoundArmor` Hediff 提供），二者叠加。

### 4.2 完整算例：近战伤害（`baseStat = 20`）

> **选择预算（关键）**：一个阶位有 40 级，每升 1 级只给 **1 次 A 类 3选1**（可选普通属性或特殊变异）。因此 Tier 内你总共只有 **40 次选择**来分配"普通属性成长"与"特殊变异层数"。想多拿体型，就得少投普通属性——二者**共享预算**，不能"40 次普通 + 3 次体型"同时满额获得。

#### Tier1（每级成长 2.0，普通属性硬上限 100）
- 基线：20
- 每级选"近战伤害"得到的增长：20 × 0.10 × 1.0 = 2.0
- 普通属性硬上限：20 × (3 + 2×1) = **100**
- **情景 A（全投近战）**：40 次全选近战 → 20 + 40×2.0 = **100**（正好到上限，未提前封顶；体型 ×1 → 终值 100）。
- **情景 B（37 次近战 + 3 次体型）**：近战 = 20 + 37×2.0 = 94；3 层体型 = ×2.5 → 94 × 2.5 = **235**（若想近战也到 100，就必须把 40 次全投近战、放弃体型）。
- **情景 C（分散投资）**：例如 20 次近战 + 10 次攻击速度 + 3 次体型 + 7 次 HP/护甲 → 各类按各自 g 与上限成长，体型 ×2.5 作用于全部普通属性终值。

#### Tier2（突破：重置普通属性，继承上一阶硬上限 100）
- 新基线 = 20 + 0.35 × (100 - 20) = **48**
- 每级增长：20 × 0.10 × 1.5 = 3.0；硬上限：20 × (3 + 2×2) = **140**
- **情景 A（全投近战）**：48 + 40×3.0 = 168 → 截断 **140**（Lv31 到顶）。
- **情景 B（37 近战 + 3 体型）**：近战 = 48 + 37×3.0 = 159 → 截断 140；含体型 ×2.5 = **350**。

#### Tier3
- 新基线 = 20 + 0.35 × (140 - 20) = **62**；每级 4.5；上限 180
- 情景 A：62 + 40×4.5 = 242 → **180**。情景 B：180 × 2.5 = **450**。

#### Tier4
- 新基线 = 20 + 0.35 × (180 - 20) = **76**；每级 6.75；上限 220
- 情景 A：76 + 40×6.75 = 346 → **220**。情景 B：220 × 2.5 = **550**。

**结果曲线（情景 B：37 近战 + 3 体型，即带体型乘区）**：
- Tier1 Lv40 = **235**；Tier2 Lv40 = **350**；Tier3 Lv40 = **450**；Tier4 Lv40 = **550**。
- 若选情景 A（放弃体型、堆满近战）：Tier1=100 → Tier2=140 → Tier3=180 → Tier4=220（数值更纯但无体型乘区，综合战力反而低于情景 B）。

> **设计意图**：Tier1 满级兽（含体型）约 235，≈ 2~3 名基准殖民者；Tier4 满级约 550，≈ 5~7 名。到达普通属性上限后，剩余等级被迫投向其他普通属性或特殊变异/技能，避免单属性无限堆叠。

### 4.3 为什么不会无限爆
- 普通属性被硬上限夹住（100→140→180→220）。
- 体型最多 3 层，固定 ×2.5，不会继续叠。
- 高阶虽然每级成长更高，但上限提升速度更慢，导致在 Lv30 左右就触及上限，剩余等级必须分配给其他奖励（或投向特殊变异/技能）。
- 仿生反馈（Phase 2）和血脉被动（Phase 2）在硬上限之后作乘区，也各有自己的递减/层数上限。

### 4.4 唯一计算顺序（不变）
```
[ tierBase + 普通属性累加 ] → 截断到硬上限 → × 特殊变异乘区 → × 血脉被动（Phase2） → × 仿生反馈（Phase2） → × 后勤补偿（德鲁伊/虫族 ×1.15）
```
只有第一段受硬上限约束。

## 5. 3 选 1 奖励系统（v0.10.1 明确普通/特殊/技能边界）

- **不再即时弹窗**。升级只把奖励压入 `pendingRewards` 队列；玩家空闲时点召唤师 gizmo 的「未决奖励」一次性逐个选择。

## 7. 召唤兽类型与特殊规则（v0.9 重写，解决类人连锁问题）

### 7.1 核心裁定：魂缚契约兽（v0.10 修订）

> 全部召唤兽都是 **魂缚契约兽（Bound Beast）**：自定义 Pawn 类型。它**不是普通动物**，也**不是殖民者**（影子例外，见 §11）。
> - 身体使用动物/人形/机械模板（德鲁伊 MVP 用 Wolf/Bear/Bird，亡灵/影子用 Human，机械用 Scyther/Centipede/Lancer，虫族用 Megascarab/Megaspider）。
> - 由玩家完全操控（可 draft、可指定工作、可手术、可受伤致残）。
> - 技能/工作等级/兴趣（双火）存储在 `BoundSummonComp` 中，不走原版殖民者技能系统；但对外表现与殖民者技能等价（工作速度按 Comp 技能计算）。
> - **需求系统按血脉差异化（§7.2）**：德鲁伊关闭心情、保留吃饭/睡觉；需要吃饭+睡觉的兽视为"后勤 debuff"，给予基础属性补偿；影子关闭全部需求。
> - **不可被绑架、逮捕、处决、贩卖（普通魂缚兽）**。敌人不会把它当囚犯处理；它是灵魂绑定单位，被击倒后由锁血/灵魂界机制保护，不会沦为俘虏。
>   - **例外——混沌影子（§11）是 `isColonist=true` 的殖民者类型**，可被绑架（与小人类似），但召唤师可远程召回。
> - **威胁点计入（v0.10 重大修订）**：魂缚兽是强力战力，系统应当据此匹配袭击强度。普通魂缚兽虽不是殖民者，但其战力通过 §16.1 的精确补丁计入袭击威胁点（不会重复计数）；影子作为殖民者由原版自然计入。
> - **机械系兽不是 Biotech 机械体**：不需要机械师控制；由召唤师灵能/契约驱动。但可安装"机械仿生"部件（来自其他 mod，如 Android Tiers 等），本 mod 不限制。
> - **仿生可安装（v0.10 新增）**：魂缚兽使用标准 BodyDef，可接收来自其他 mod 的仿生/机械部件 Hediff（动物仿生、机械仿生等）。仿生反馈**无封顶**（继承早期设定）。具体可用部件取决于玩家订阅的仿生 mod；本 mod 仅在 `BoundSummonComp` 中**不做任何限制**。
> - **自带基础护甲（v0.10 新增，CE 兼容）**：魂缚兽**没有装备栏**（无法穿甲/穿衣服），因此自带较高的 `ArmorRating_Sharp` / `ArmorRating_Blunt` 基础护甲，并随阶位/阶内等级自动成长（§7.2 / §21）。CE（Combat Extended）读取的是 `ArmorRating_*` 属性值，与装备无关，因此天然兼容；即便不装 CE，高基础护甲也能让兽在面对枪械时存活更久。

### 7.2 按血脉区分需求与能力

| 血脉 | 身体模板 | 吃饭 | 睡觉 | 心情 | 可穿装备 | 仿生 | 自带护甲 | 后勤补偿 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 德鲁伊 | Wolf / Bear / Bird | ✓ | ✓ | ✗(关) | ✗ | ✓(动物仿生mod) | ✓(随级) | **+15% 基础HP/近战/移速** | **MVP 三兽** |
| 亡灵 | Human | ✗ | ✗ | ✗ | ✗ | ✓(骨架/机械mod) | ✓(随级) | — | 人形骨架，无机需求 |
| 元素 | Human/Wolf | ✗ | ✗ | ✗ | ✗ | ✗ | ✓(高) | — | 无机生命，护甲高 |
| 机械 | Scyther/Centipede/Lancer | 供能 | ✗ | ✗ | ✗ | ✓(机械mod) | ✓(高) | — | 需 Biotech 带宽(Phase2) |
| 虫族 | Megascarab/Megaspider | ✓ | ✓ | ✗ | ✗ | ✓(动物mod) | ✓(随级) | **+15%** | 有机 |
| 混沌影子 | Human(克隆本体) | ✗ | ✗ | ✗ | ✓(同殖民者) | ✓ | ✓(随级) | — | **殖民者类型**：isColonist、可绑架、可召回(§11) |

> **后勤补偿规则（v0.10）**：凡需要**吃饭+睡觉**的兽（德鲁伊、虫族），因承担后勤负担（喂食/铺床/不能长期离基地），其基础 HP / 近战伤害 / 移速 额外 **+15%**（`upkeepCompensation`，待实测）。影子、亡灵、元素、机械无此类需求，不享受该补偿——以"手感便利（免后勤）"换"面板数值"。该补偿与 §4 的普通属性成长、变异乘区**正交叠加**（先算 §4 最终值，再整体 ×1.15）。

### 7.3 锁血与死亡规则（v0.10.1 状态机）

#### 7.3.1 五种状态

| 状态 | 含义 | 能否召回 | 能否再契约/沉睡 | 锁血是否可用 |
|---|---|---|---|---|
| **Active** | 在场上，可被控制/战斗/工作 | 已在场上 | 可操作沉睡 | ✓ |
| **Retreated** | 锁血触发后退回灵魂界 | ✓ 随时 | 可切换到 sleeping / 可换主兽 | ✗（已触发，等待 CD） |
| **Sleeping** | 玩家主动沉睡（单只兽） | ✗ 该兽 3 日内不可 | 该兽不可召回；同槽其他备用兽可被顶上主兽（无 CD） | ✓（沉睡中不受伤/不消耗） |
| **Lockout** | 锁血 CD 中，但兽仍在场上或被提前召回 | — | — | ✗（此时濒死 = 真死） |
| **Dead** | 真死亡 | ✗ | ✗ | ✗ |

#### 7.3.2 锁血触发条件
- 当兽满足以下任一条件时自动触发锁血退回：
  - 意识（consciousness）即将归零；
  - 任一关键部位（头/躯干/心脏等）受到致命一击且该击会导致死亡；
  - 疼痛或失血导致即将倒地。
- **不再看固定 HP 百分比**。
- 触发后：自动包扎全部伤口 → 状态变为 **Retreated** → 退回灵魂界 → 进入锁血 CD = **1 游戏日（60000 ticks）**。

#### 7.3.3 锁血 CD 期间的关键规则
- **Retreated 状态的兽**：在灵魂界中，**随时可以被召回**；但召回后仍处于锁血 CD，若再次濒死则真死。
- **Sleeping 状态的兽**：在灵魂界中，**3 日内不可召回**，因此也免疫这 3 日内的所有伤害/死亡。
- **Lockout 状态**：若玩家通过 bug、mod 冲突或其他机制在锁血 CD 中强行让兽留在场上并再次濒死，则直接真死。

#### 7.3.4 非战斗死亡处理
- **疾病、饥饿、冻伤、中暑**等不会导致真死亡。
- 魂缚兽处于 Active 状态时若因非战斗原因濒死，同样触发锁血退回 Retreated；伤口会被包扎，饥饿/疾病状态暂停恶化（灵魂界中不消耗食物、不触发疾病进程）。
- 召回后若疾病/饥饿仍未解决，兽会继续恶化，再次濒死时会再次触发锁血；但若在锁血 CD 中再次濒死 → 真死。
- 因此玩家必须保证召回后兽有食物、温暖、医疗：这构成了德鲁伊/虫族的"后勤 debuff"设计意图。

#### 7.3.5 真死亡条件（MVP 仅第 1 种）
1. **锁血 CD 中再次濒死**：兽处于 Active/Lockout，且锁血 CD 未结束，再次满足触发条件 → 无法退回 → 真死。**这是 MVP 唯一真死方式**。
2. 被**反召唤单位**的「断魂」技能命中，无视锁血直接击杀。 **Phase 2 再做**。
3. 灵魂界被「裂隙入侵」攻破，界内兽批量真死。 **Phase 3 再做**。

> **注（v0.10）**：混沌影子虽为殖民者（`isColonist=true`），但仍持有 `BoundSummonComp`，**锁血退回与真死亡判定对其同样生效**；其被绑架风险由「远程召回」（§14）对冲——被抓后召唤师可立即召回，避免沦为长期俘虏。

## 10. 复活与灵质（MVP，v0.10.1 补齐数值）

### 10.1 复活消耗
- **基础消耗**：`reviveCost(tier) = 5 × 1.6^(tier-1)` 单位灵质。
  - Tier1 = 5；Tier2 = 8；Tier3 ≈ 13；Tier4 ≈ 21。
- **召唤师 debuff**："灵魂枯竭"，持续 2 游戏日，期间召唤师全局工作效率 -20%、冥想/休息效率 -20%。
- **复活冷却**：同一兽 1 游戏日内不可重复复活。
- **无灵质**：兽保持死亡状态，不消失；获得足够灵质后可随时复活。

### 10.2 突破消耗
- **突破条件**：兽达到当前阶 40 级 + 召唤师拥有足够灵质 + 召唤师手动确认。
- **灵质消耗**：`breakthroughCost(tier) = 3 × 1.6^(tier-1)` 单位灵质。
  - 从 Tier1 → Tier2 需 3；Tier2 → Tier3 需 5；Tier3 → Tier4 需 8。
- **突破后**：普通属性按 §4.1 重置；特殊变异/技能/工作保留；等级回到 Lv1。

### 10.3 Tier4 满级后的终局规则
- Tier4 Lv40 为**当前兽成长的终点**（不再突破到 Tier5）。
- 之后每升 1 级仍触发一次 3选1，但只能从"技能精进 / 特殊变异 / 工作提升"中选择，普通属性选项被移除（已达 Tier4 上限）。
- 若玩家想继续突破，必须等待 **Phase 3「灵魂融合」**：将两只同血脉 Tier4 满级兽融合，生成新的终局形态（具体规则 Phase 3 再定）。

### 10.4 灵质来源
1. **矿物（主来源）**：灵质矿脉，按原版采矿开采（稀有度高于铂金/铀）。单矿脉产出 10~30 单位灵质。老存档可用深钻机/长程扫描仪找到。
2. **击杀敌方召唤师（额外来源）**：Phase 2 事件，非 MVP 必需。
3. 任务奖励（少量，1~3 单位）。

## 16. 平衡（v0.9：MVP 只留最基础的）

### 16.1 MVP 必须做
- **栏位上限限制上场兽数**：同一时刻 Active 兽受 `maxSlots` 约束，无法铺军团。
- **普通属性硬上限 + 特殊变异层数上限**（§4）。
- **锁血兜底 + 真死亡三种条件**（§7.3）。
- **威胁点计入（v0.10 移入 MVP，待编码实现）**：通过 Harmony 补丁，将场上普通魂缚兽的战力折算进袭击威胁点，使系统匹配更强的袭击。
  - **补丁目标**：`StorytellerUtility.DefaultThreatPointsNow(Map)`（或等效的袭击威胁点入口；若该入口在所用 RW 版本已被重构，则改补 `IncidentWorker_Raid` 的威胁点计算）。
  - **计入口径**：对每个 `isColonist == false` 且持有 `BoundSummonComp` 的场上 pawn，累加其 `PawnCombatPower`（原版方法，已含装备/能力/健康），乘以系数 `threatPointFactor`（建议 0.8~1.0，待实测）后加入威胁点。
  - **不重复计数**：普通魂缚兽不是殖民者，原版威胁点计算本来就不计入它们；我们只在补丁里精确加上这部分，不存在双重计入。
  - **影子豁免**：影子是 `isColonist=true`，其战力已被原版殖民者威胁点自然计入；补丁里用 `isColonist` 判断跳过，避免重复。
  - 这样"你养了一支强力兽群"会真实地换来更硬的袭击，符合"强力战力要被系统考虑"的设计意图。
  - **当前状态**：设计已确定，C# 代码仍属骨架，MVP 实现顺序见 §20 Phase 1 第 7 步（威胁点补丁与存读档并行）。

- **血脉阶 `schoolTier`**。
- **精英/反召唤单位**：裂隙猎手从特定威胁等级开始出现。
- （威胁点机制 MVP **设计已确定、C# 骨架待实现**；Phase 2 仅把其余血脉接入同一套 §16.1 补丁逻辑，无需重新设计。）
