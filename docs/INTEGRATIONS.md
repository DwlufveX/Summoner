# 幻想生物 Mod 联动开发方案

更新日期：2026-10-28。

后续以生物包联动为主：由来源 Mod 提供生物、贴图、身体结构、声音和原生能力，Summoner 提供契约、编队、灵境、成长与复活。暂停独立扩绘召唤兽四向素材，优先完成生物接入。现有 0.3 三兽保留作原型、回归夹具及存档兼容，不据此继续扩建独立兽库。

**当前只有内置三兽实现；本页列出的外部生物包均未完成适配或游戏验收。** 2026-10-28 已检查本机安装的 Alpha Animals，包括 About、双版本加载目录、候选生物定义与部分原始贴图；其余下表候选以作者页面核对为主，未读取实际安装文件。基础 Mod 的 1.6/1.7 验收不能转用于第三方生物包。

本轮筛选建议：**Alpha Animals 先做双版本接入试点，Dark Ages 作为后续奇幻主题重点，龙类在普通生物与原生技能接入稳定后再做。** 这是基于当前文件、版本声明和项目控制方式的开发判断，不是兼容测试结论。

## 游戏怎样组合

玩家启用 Summoner 和已支持的生物包，按照该生物的接入规则完成救援或获取，再建立契约。呼唤出来的是来源 Mod 的原生 Pawn，沿用它的种族与外观；Summoner 记录主人、编队、成长和状态，并管理真实实体进出灵境。

不把狮鹫简单改名为灵鹰，也不把所有外部动物统一套上内置狼熊鹰的数值。血脉是培养与契约分类，物种由来源包决定。每种接入生物单独配置定位、体量、初始获取条件和成长边界。现行每槽一主三备、上场容量与轮换约束继续适用。

来源 Mod 的贴图、程序集与其他资源不复制进本仓库或发布包。玩家自行安装来源包和它要求的框架；本项目保存映射、适配代码、来源链接与验证记录。图标、编队界面和必要的召唤效果仍可自行制作。

### 影响首发选择的限制

- Dark Ages 的作者页面明确限制未经授权再利用其作品。联动保持来源包外部安装，仓库不复制其贴图、声音或代码；正式公开联动前应核对作者对具体适配方式的要求，不能沿用旧的 CC BY 4.0 说明。
- Menagerie 的作者页面仍列出与 Dragons Descent 的远程动物框架冲突，涉及龙无法近战。该条是否已被新版本修复需要实测；不能分别能运行就推断二者与 Summoner 同时启用也能运行。
- Dragons Descent 有原生年龄阶段成长；Menagerie 有石化、多种射线、构造与召唤获取。它们适合作为后续内容扩展，接入成本判断来自这些原生机制，而非单看贴图数量。
- Monster Hunter Legacy 已停止更新，后继页面与 Witcher Monster Hunt 的标记也不足以支持当前双版本首发。继续保留美术与玩法参考价值，暂不放入首批依赖。

## 接入层需要做什么

### 生物档案和白名单

每个档案使用稳定的本项目 ID，并记录真实的来源 packageId、允许的游戏/来源版本、ThingDef、PawnKindDef、血脉、角色、体量、获取条件、攻击适配方式与来源能力边界。Workshop ID、显示名称与 packageId 是不同字段；不能根据英文名猜 Def。

只有对应来源包启用且所需定义齐备时，档案才可用。名单内也不是所有野生个体都能直接缔约：需区分救援对象、已驯服个体、敌对任务单位与 Boss，避免点击一次就把野外强敌收走。

目前 `SummonerAdventure` 的救援池写死为 RMS 三兽；`SummonerGameplay` 与 `SummonerCommands` 通过本项目的扩展和组件识别生物。这些入口需要改为生物档案查询，不能只新增几个贴图路径。

### 保留来源行为

不全局替换来源种族的思考树、身体、需求、原生攻击和技能。契约前的野生生物应保持原状；契约后的征召与轮换也不能让普通野生个体取得召唤师控制。

0.3 的服从/搬运训练和“选第一个远程 Verb”逻辑是内置三兽实现，不能直接套用给飞龙、构装体或带多个技能的怪物。原生技能按钮优先保留，控制与能力适配按档案单独验证。近战、远程、吐息、多部位攻击和飞行不视为同一种接口。

来源包已有年龄或等级成长时，先明确与召唤师阶位的关系，再决定增量和上限；不默认把两套成长倍率叠加。旧的狼熊鹰示例数值不作为所有外部物种的统一基线。

### 真实实体与存档

继续保存同一个 Pawn，不在每次呼唤时重建替身。来源的组件、健康、能力冷却、装备与物品需要随实体保留；依赖地图的注册或缓存由适配钩子在离场/进场时处理。

存档应保存稳定档案 ID 及来源身份。读取时检测来源缺失或档案不匹配，明确指出需要的生物包；不把缺失的龙静默变成内置狼。原版、fork、换皮包与改名后的 Def 均需显式映射，不能自动当成等价替换。

## 第一轮交付

1. 取得首个来源包的正式版本，读取 About、LoadFolders、Defs 与组件；确定真实 ID、依赖和 1.6/1.7 的可运行范围。
2. 选三种以内、行为简单的生物，建立白名单与获取规则。先通一只近战，再增加承伤与远程。
3. 将救援池与可契约识别从内置种族切到档案查询，保护来源种族原本行为，接入真实实体的呼唤/召回/轮换。
4. 每个适用版本验证：加载、获取、契约、容量、征召、攻击/能力、两轮存读档与读档后继续操作。
5. 额外验证来源包关闭、原包与 fork 不匹配、未打开牢笼保存、冷却中的实体召回，以及未契约的同种野生个体。
6. 验收通过后才在仓库首页列为“已支持”；飞龙、石化、变形、坐骑与构装体按独立案例继续扩展。

按本轮筛选，建议首包使用 Alpha Animals，先以 Meadow Ave 打通控制与存档，再验证 Nightling 的原生技能。Dark Ages、Grimstone 和 Anima Animals 保留后续候选身份；当前不发布没有真实 Def 和运行证据的空兼容补丁。

## 现有原型怎样处理

保留 RMS 三兽定义、已验证的数据模型和原型素材，使既有存档、无来源包环境及基础回归仍可使用。旧图在首页标为原型，不再作为后续美术工作重点。具体来源接入前，游戏运行行为保持 0.3 状态；本次只变更开发方向和接入方案。
