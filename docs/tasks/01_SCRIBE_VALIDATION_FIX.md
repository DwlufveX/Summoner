# 第一轮存档验证收尾任务

执行者：Cursor 中的 Grok。工作区：`E:\Project\Summoner`。

先阅读[返修复查结果](01_DATA_FOUNDATION_RECHECK.md)。R1–R3 已确认修复，本轮只处理 R4 及验证报告，不扩展玩法，不重做已通过的代码。

## 必须修正

1. 对每次完整加载采集该阶段新产生的关键保存/读取诊断。不能仅依赖外层异常和 `Scribe.mode`。`Could not resolve cross refs`、`Could not do PostLoadInit` 等内部错误必须导致该加载失败，阻止 `ENTITY PASS`、`TryRun=true` 和宿主退出码 0。
2. 分清内存约束、纯字段读取、完整记录加载、完整实体加载四类结果。已验证的字段可以保留证据，但整体加载失败不能归为通过。
3. 增加一个回归场景：加载调用正常返回，却记录关键内部错误。测试必须失败；连续执行后诊断缓冲区和 Scribe 状态应正确清理。
4. 不以屏蔽交叉引用错误、跳过 Pawn 加载后初始化或关闭日志方式取得通过。测试宿主已有的 `NotifyAdded` 补丁仅能作为受限制的隔离验证，不得视为完整游戏证据。
5. 当前开发者按钮允许在 Playing 状态运行，但实体段直接拒绝有 `Current.Game` 的环境。提供适用于隔离游戏场景的验证入口，或明确该按钮只支持部分检查。测试 Def 的注入限制应在所有使用它的阶段生效；目前 `RunBindingRegression` 也会调用 `IsolatedThingDef`，不能只在 `RunEntity` 中检查。

## 游戏验证与环境限制

能建立完整游戏测试环境时，使用真实主人、地图/世界兽和界内兽验证绑定成功路径、完整交叉引用、加载后初始化、伤病、容器与组件外键。

延续原任务约束，不自动安装 Mod 到游戏目录、不操作正式殖民档。如果目前仅能运行隔离宿主，则将关键错误判为未通过，列出环境缺口和可复现步骤；不要求修补游戏自身代码或强行初始化 Unity 原生接口。

即使游戏实测暂不能完成，也要先完成诚实的结果判定。代码修正完成、内存通过、实体环境未通过应分别报告。

## 交付

运行 `Tools/Build.ps1`、`Tools/Verify-Package.ps1` 和必要回归。写入 `docs/tasks/01_SCRIBE_VALIDATION_FIX_RESULT.md`，包含每阶段结果、关键错误数量、宿主退出码及尚未完成的游戏验证。根据实际证据更新 `docs/STATUS.md`，保留此前报告。

完成后等待复查，不进入第二轮功能扩展。
