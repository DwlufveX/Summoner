# 第一轮返修任务 数据一致性与完整存读

执行者：Cursor 中的 Grok。工作区：`E:\Project\Summoner`。

本轮保持第一轮数据层范围，不进入新玩法和美术接入。先阅读[审阅结果](01_DATA_FOUNDATION_REVIEW.md)、[原任务单](01_DATA_FOUNDATION.md)和现有交付报告。

## 修复内容

1. **R1 实体绑定一致性**：同一兽 ID 改绑不同 Pawn 必须拒绝；同一实体的重复绑定应安全。检查界内条目与记录双向对应关系，拒绝产生同 ID 两个实体或悬空条目。失败保持旧状态。若需要容器释放与重新绑定，以明确且可验证的原子操作处理，不在保存过程中悄悄丢弃唯一实体所有权。
2. **R2 容量一致性**：修改体量和容量前检查最终占用；拒绝超限，并保留修改前的值。新增覆盖修改体量、缩减容量、未在场备用兽及失败后回滚的回归验证。
3. **R3 奖励对象归属**：验证目标存在、类型与所属召唤师匹配；拒绝跨主人及不存在目标。一致性检查也要识别加载后的无效目标，失败不增加队列或推进 ID。
4. **R4 测试结果真实性**：完整加载未完成时不得报告 `SCRIBE PASS` 或将 `TryRun` 作为完整通过。纯字段序列化和完整加载分别报告；不吞掉异常伪装成功，失败正确清理全局 Scribe 状态。

## 实体验收

准备显式开发者入口与可复现的隔离测试场景，覆盖以下内容。未经实际运行不得写为通过。

- 真实主人引用、场上兽引用、界内深度保存兽都在完整加载后恢复。
- 核对 Pawn ThingID、伤病、记录 ID、主人关联、容器持有关系、组件外键与冷却。
- 核对界内 Pawn 的嵌套持有者遍历；按标准 `IThingHolder` 约定实现必要的子持有者枚举。
- 同一兽改绑不同实体、同一实体绑定不同兽、不同实体重复使用同兽 ID、保存前重复持有等错误路径均有验证。
- 加载后继续分配 ID 不重号；连续运行测试不污染下一次 Scribe 保存/读取。

测试不得操作正式殖民档。延续原任务的范围约束，不自动安装 Mod 到游戏目录；若隔离运行尚缺条件，记录实际限制与复现步骤，明确区分代码已修、内存验证已过和游戏验证待完成。
